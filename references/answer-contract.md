# 回答契约

## JSON 结构

```json
{"question":"用户原问题","conclusion":"不超过40字的总判断","reading_path":["先看哪一枝","再看哪一枝"],"root":"中心标题，可\\n换行，不超过两行","branches":[{"id":"b1","label":"① 目标锁定","children":[{"label":"只做一项目","children":[]}]}]}
```

只要求节点具有 `label`；缺省 `children` 视为空数组。根节点只有一个。一级颜色按阅读序号自动分配。

## 建树规则

- 一级枝使用 5–9 个；3–4 个可渲染，但校验器发出警告。
- 默认最大深度为 L3。L4/L5 只能位于最多 2 条一级枝。
- L3 及以上节点总数超过 18 时，改为总图只到 L2，并说明哪些枝可另图展开。
- 一级标签必须依次带 ①②③④⑤⑥⑦⑧⑨。
- 中文节点以 2–8 字为佳，硬上限 12 字符；英文使用 1–6 个词。
- 使用名词短语解释概念，使用动宾短语表达流程。保持同级词性一致。
- 不用完整句子，不设空装饰节点，不用“其他”“补充”“总结”作一级枝，除非用户要求行动清单。

## 题型路由

| 题型 | 一级拆法 | 深度 |
|---|---|---|
| 解释概念 | 是什么、为什么、怎么用、边界、误区 | 默认 L3 |
| 对比选型 | 场景、各方强项、约束、怎么选、误区 | 默认 L3 |
| 规划学习或项目 | 目标、路径、节奏、坑、验收 | 默认 L3 |
| 排查故障 | 现象、分层假设、验证、处理、预防 | 默认 L3，关键假设可到 L4 |
| 做到上线或实施方案 | 问题、方案、实现、验证、发布、复盘 | 实现与发布可到 L4/L5 |
| 强时序、协议、状态机 | 只保留阶段名，并声明应改流程图 | L2–L3 |

## 文本输出

```text
## 结论
...
## 阅读路径
1. ...
## 结构大纲
- 根
  - 一级
    - 二级
## 思维导图
[图片文件路径]
```

先建树与渲染，不要先写长文。大纲必须与 JSON 树同构。
